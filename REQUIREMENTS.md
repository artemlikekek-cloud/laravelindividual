# Требования к проекту "Онлайн-запись на СТО"

## Описание проекта

Веб-приложение для автосервиса, позволяющее клиентам записываться онлайн на обслуживание автомобиля. Администратор может управлять записями через панель управления.

---

## Основные функции

### Для клиентов:
- Просмотр информации о СТО и услугах
- Выбор нескольких услуг одновременно
- Автоматический расчет времени и стоимости
- Выбор даты записи
- Просмотр свободного времени
- Заполнение контактных данных
- Получение подтверждения записи

### Для администратора:
- Вход в систему (авторизация)
- Просмотр всех записей
- Изменение статуса записей
- Удаление записей
- Выход из системы

---

## Технические требования

### Backend:
- **Фреймворк:** Laravel 11
- **Язык:** PHP 8.2+
- **База данных:** PostgreSQL
- **Архитектура:** MVC с применением Repository и Service паттернов

### Frontend:
- **Шаблонизатор:** Blade
- **Стили:** CSS3 с Flexbox
- **JavaScript:** Vanilla JS (без фреймворков)
- **AJAX:** Fetch API для загрузки времени

### Безопасность:
- CSRF защита (Laravel токены)
- Валидация данных на сервере
- Хэширование паролей (bcrypt)
- Middleware для защиты админ-панели

## Структура базы данных

### Таблицы:

1. **users** - администраторы
   - Поля: id, name, email, password
   - Связи: нет

2. **services** - услуги СТО
   - Поля: id, name, duration_minutes, price, description, is_active
   - Связи: many-to-many с appointments

3. **appointments** - записи клиентов
   - Поля: id, client_name, client_phone, client_email, car_model, appointment_date, appointment_time, total_duration_minutes, total_price, status, notes
   - Связи: many-to-many с services

4. **appointment_services** - связующая таблица
   - Поля: id, appointment_id, service_id
   - Связи: foreign keys на appointments и services

5. **working_hours** - график работы
   - Поля: id, day_of_week, start_time, end_time, is_working
   - Связи: нет

### Связи:
- Appointments ↔ Services (many-to-many через appointment_services)

## Принципы проектирования

Применены принципы SOLID:

1. **Single Responsibility** - каждый класс отвечает за одну задачу
   - Контроллеры - HTTP запросы
   - Сервисы - бизнес-логика
   - Репозитории - работа с БД

2. **Open/Closed** - можно расширять без изменения существующего кода
   - Использование интерфейсов

3. **Liskov Substitution** - замена реализаций через интерфейсы
   - Репозитории реализуют интерфейсы

4. **Interface Segregation** - маленькие специализированные интерфейсы
   - Отдельные интерфейсы для каждого репозитория

5. **Dependency Inversion** - зависимость от абстракций
   - Внедрение зависимостей через конструкторы

```
Routes → Controllers → Services → Repositories → Models → Database
```

**Слои:**

1. **Routes (web.php)** - определяет URL и связывает с контроллерами
2. **Controllers** - принимают HTTP запросы, возвращают ответы
3. **Services** - содержат бизнес-логику
4. **Repositories** - работают с базой данных
5. **Models** - представляют таблицы БД
6. **Views** - отображают данные пользователю

## Основная логика

### Процесс записи клиента:

1. Клиент выбирает услуги → JavaScript считает итого
2. Клиент выбирает дату → AJAX запрос к серверу
3. Сервер проверяет рабочие часы → генерирует слоты каждые 30 минут
4. Сервер проверяет занятые слоты → возвращает свободные
5. Клиент выбирает время и заполняет данные
6. Форма отправляется → валидация на сервере
7. Проверка конфликтов времени → сохранение в БД
8. Возврат сообщения об успехе

### Алгоритм проверки конфликтов:

Два временных интервала пересекаются если:
```
newStart < existingEnd AND newEnd > existingStart
```

Пример:
- Новая запись: 14:00 - 15:15
- Существующая: 13:00 - 13:45
- 14:00 < 13:45 = FALSE → нет конфликта

## Особенности реализации

### 1. Пошаговая форма записи
Форма разделена на 4 шага для удобства:
- Шаг 1: Выбор услуг
- Шаг 2: Выбор даты
- Шаг 3: Выбор времени
- Шаг 4: Данные клиента

### 2. Динамический расчет
JavaScript в реальном времени считает:
- Количество выбранных услуг
- Общее время обслуживания
- Общую стоимость

### 3. AJAX загрузка времени
При выборе даты и услуг отправляется запрос на сервер без перезагрузки страницы. Сервер возвращает только свободные слоты.

### 4. Адаптивный дизайн
CSS Flexbox обеспечивает корректное отображение на всех устройствах (десктоп, планшет, мобильный).

### 5. Защита административной панели
Middleware проверяет авторизацию перед доступом к админским страницам. Неавторизованные пользователи перенаправляются на страницу входа.
